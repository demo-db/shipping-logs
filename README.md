# Shipping original logs

This repository prepares the original synthetic Shipping JSONL evidence as a
native inGitDB database, served read-only through OpenVaultDB at
<https://ovdb.demodb.dev/v1/databases/shipping-logs>
(`capabilities.ovdb.deploymentVerified` in `manifest.json`; the endpoint
answered on 2026-10-22 with the three original collections). The three
carrier-gateway collections added in this revision are served once the
OpenVaultDB provider pin is moved to this revision; until then the endpoint
serves the previous revision.

The database contains six deliberately separate collections:

- `baseline`: 29 original observations used by the investigation.
- `recovery11045example`: three hypothetical replay events for order 11045.
- `recovery11062example`: three hypothetical replay events for order 11062.
- `carrierGateway`: the synthetic carrier-gateway booking call of healthy
  order 11038 (request and `booked` confirmation). Blocked orders 11045 and
  11062 have no call before their replay.
- `carrierGatewayRecovery11045example` and
  `carrierGatewayRecovery11062example`: each order's hypothetical replay
  booking call, eligible only together with that order's recovery example.

The recovery collections are future examples, not baseline observations. A
booking is not a pickup or package movement; no real carrier or shipment is
represented. Every record retains the original `event_id`, `occurred_at`,
`clock_domain`, `precision_ms`, and `synthetic` fields. `event_id` is the declared inGitDB
primary key. No `$ID` field is added and no SQLite, parsed-row database, cache,
or snapshot is created.

The JSONL files, `source-manifest.json`, and CC0-1.0 license are copied
byte-for-byte from public `datatug/datatug-demo-project` revision
`8c17604ee3f971ea70b3aa9490176e798e267d3a`. `manifest.json` pins the size,
row count, and SHA-256 of each original file. The source manifest retains the
per-entry byte ranges and digests.
The fixture was introduced at revision
`38a51dda39d988f2d2bcf23703bd1a969d49f4a3`; the three original JSONL files are
byte-identical at that revision and the pinned source revision, which adds the
three carrier-gateway files and lists them under `carrierGatewayLogs` in the
source manifest.

Provider metadata and the deterministic inGitDB archive are generated by the
immutable DemoDB website generator. CI verifies the generator digest,
regenerates all outputs, runs the native DAL query and keyed-read test with
`github.com/ingitdb/dalgo2ingitdb` v0.7.1, and rejects any changed file.

```sh
python3 /path/to/demo-db-websites/scripts/provider-tools/generate_ingitdb.py --root .
go test -count=1 ./...
git diff --exit-code
```

The read-only OVDB endpoint declares native collection schema, query, and
keyed-read capabilities (observed 2026-10-22). The relationship to Shipping identifies matching event IDs;
it does not claim a cross-database foreign key, automatic join, or federation.
